## Bounded implementation evidence (2026-09-30)

- F01/F02/F04/F12: `src/DeskNest.App/Views/StudioView.axaml`, `DropCapsuleWindow.axaml`, `Services/HeadlessSmokeRunner.cs`, `src/DeskNest.Platform/PlatformFileActions.cs` and `ManualOrganizationCoordinator` supply the current entrypoints. The Windows headless suite checks actual production views, 287-key parity across twelve languages, keyboard/DnD callback routing, and bounded 10k virtualization. It does **not** prove real Explorer/Finder/Nautilus negotiation, desktop compositing, IME or assistive-technology behavior. Production Copy/copy-Paste remains gated regardless of the internal copy tests.
- F11: `build/Publish-Windows.ps1` and `build/windows/Install.ps1` provide the unsigned development lifecycle. Installed main-window and Core recovery-probe results are recorded in [the P3 report](p3-report.md); they do not establish signing, secure updates, backup of managed files, clean-machine support or full F11 acceptance.
- F13 follow-up: the file-row **Local Laya classification preview** command invokes the real CPU worker with a trusted offline model bundle and displays ranked ordinary/special candidates without reading file contents or changing files/metadata. The opt-in headless check used the pinned multilingual bundle; it does not establish Jev, deployment, quality, automatic classification or installed inference acceptance. See [P4 partial report](p4-report.md).
- F10 follow-up: the independent space window can explicitly save its position/size, then restore within an available screen when reopened. Store round-trip and headless window checks pass; automatic startup restoration, physical hotplug and mixed-DPI behavior remain unverified. See [P3 report](p3-report.md).
- “部分” means the listed subset has a runnable entrypoint and evidence, not that the entire row or phase has passed. Earlier cross-platform P1/P2 probe results must not be presented as execution of the latest Windows-only P3 changes.
