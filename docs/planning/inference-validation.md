# 栖格 · DeskNest：原生推理与分类闭环验收

> 实施规范，不是测试结果。用户端只有打包的原生 worker；Python/PyTorch 仅在开发与 CI 生成参考结果。数值接近、接口等价、决策安全、实际分类质量分别验收，不能互相替代。

## 1. 本轮源码发现

- Laya `laya-ts/scripts/export_onnx.py` 本轮 blob 为 `d82f7f28c70cd884ea0c48e0dddf4648612bc3cf`。开发期补丁 [`export-strict.patch`](../../tests/Inference.Tests/export-strict.patch) 为 PyTorch 2.7 的 `dynamic_shapes` 启用 `dynamo=True`、要求 safetensors 严格加载，并在导出捕获前克隆普通临时张量；补丁 hash 与最终图/external-data hash 由 `package_probe.py` 记录。不能把这些保护措施归因于未修改的上游脚本。
- `_run_ref` 使用全 1 token、全 1 attention mask、固定两个 marker，覆盖部分 batch/长度；其 head 参考还是导出脚本内的 `_HeadOnly`。这种自我对照无法检出双方共享的实现错误，也不覆盖真实文本、padding、完整分词和校准。
- 实际 head 输入包括 `attention_mask`，尽管脚本文档开头只列四个参数。不能按注释写 ABI，必须检查导出图的名称、dtype、rank、shape。
- `laya-ts/src/common.ts`（blob `323bad34496524c09126009078d0ca9fdb34b0c1`）显式模拟 Python JSON 分隔符；拼接顺序、mask token 替换、选项截断与状态截断影响 token ID。`confidenceFromProbs` 是熵指标，而 `answerConfidence` 是 max(p)，二者不同。
- `laya/onnx_agent.py`（blob `523264042c08cf217027aeab4cd312b14757661e`）有按问题类型/候选数的温度桶、温度裁剪、四位小数响应，且其单图 ONNX 接口不是本项目 split encoder/head worker 的直接替代品。
- 三个 blob 来自逐文件读取，不冒充同一已固定 commit。P0 已固定同一 Laya commit 与模型 revision；P1(c) 使用该固定输入完成 A–D 三路径对照，并把证据写入 [`p1-report.md`](p1-report.md)。这仍是小规模等价性探针，不是 500+ 样本分类质量门槛或文件移动闭环。Python/PyTorch 仍不进入用户端包。

## 2. 冻结可复现的输入与制品

每个发布模型包记录：上游 commit、HF checkpoint revision、权重 hash、tokenizer/added tokens/normalizer 配置、完整 agent 配置、导出器补丁 hash、PyTorch/Transformers/ORT/tokenizers 版本、opset、图及 external-data hash、图 I/O schema、最大长度/候选数、温度策略、已验证 EP/精度/OS/架构。

- 产品首先支持 Choice 分类。特殊选项有稳定 ID；用户分类 ID 不依赖显示名或 i18n。请求保存有序候选快照，输出按 ID 还原，禁止按当前 UI 顺序猜测。
- 数据集包含完整 state、问题说明、分类名称/简介、有序 ID、特殊项、实际 token 预算和请求版本，不只存文件名。
- 权重加载差异必须逐项解释：确属非推理用缓冲区可列审核过的 allowlist；encoder/head 必需权重缺失或形状错误直接失败。发布导出不能使用 `--no-verify`。
- 应用将文件元数据转成规范 state 文本；内层 agent 的拼接/分词仍对齐锁定的原始实现。不擅自统一 Unicode、排序候选或更改 JSON 空白后称“语义等价”。

## 3. 四条路径拆分定位错误

| 路径 | 输入与输出 | 用途 |
| --- | --- | --- |
| A：官方 PyTorch Agent | 原始完整请求 → 官方预处理 → 原始 DecisionModel.forward → 官方校准/响应 | 独立 oracle；不以导出器自建 head 作为唯一真值 |
| B：Python ORT 双图 | A 捕获的输入张量 → 导出的 encoder/head → 参考后处理 | 隔离图导出/算子误差 |
| C：C# 诊断入口 | 同一输入张量 → 实际原生 ORT/EP → C# 后处理 | 隔离 dtype/rank/绑定/温度/输出映射问题；仅用于测试 |
| D：打包后的实际 worker | 与 A 相同的原始请求 → 原生 tokenizer/拼接/ORT/响应 → 主进程决策 | 证明用户实际执行路径，而不是仅测试旁路 |

A 的诊断捕获只观察官方预处理、输入张量和未舍入输出，不替换算法。保存每层摘要及失败样本的完整张量；正常 CI 不无界打印数组。最终真值以 A 为准，B/C/TS 包仅用于交叉定位。

## 4. 分层通过条件

| 层 | 断言 | 失败处理 |
| --- | --- | --- |
| 制品 | revision/hash/必需权重/图输入输出完全匹配；缺失 external-data、错误 head/encoder 配对被拒绝 | 不发布制品，不降级为随机初始化 |
| 预处理 | state 渲染、候选次序与映射、input_ids、attention_mask、marker_pos、marker_mask、qtype 的值/dtype/shape 与 A 精确相同 | 修原生分词/拼接/ABI，不能用 logits 容差掩盖 |
| 图数值 | CPU FP32 有效候选 logits 的最大绝对误差 ≤1e-4；所有有效输出 finite；报告 abs/relative/p95，encoder hidden 单独诊断。padding marker 不进入统计或概率 | 定位 B/C 首个偏离层；不得通过改显示舍入绕过 |
| 后处理 | 按有效候选数选择温度桶、温度裁剪、mask、softmax、ID 映射与 A 相同；未舍入 p、熵指标、answer_confidence 最大绝对误差 ≤1e-4 | 不发布该模型/worker 组合；温度配置异常的桶不允许自动移动 |
| 协议 | 必需字段/ID/type/使用量一致，无重复/缺失/额外候选；精度/舍入规则对齐，NaN/Inf/空响应拒绝。四位小数跨舍入边界允许差一个末位，但必须满足未舍入误差界且不改变动作 | 响应错误进入运行失败，不伪装低置信度 |
| 排名/决策 | 稳定样本 top-1、最高真实类别、特殊项路由和最终动作与 A 完全一致；近并列采用下述安全策略 | 稳定样本任一类别/动作不同即阻断；边界差异不可自动放行 |
| 文件闭环 | 相同输入与冻结策略经 A/D 对照得到同样的移动计划/待决原因；实际 D 路径在临时目录完成移动/撤销/崩溃恢复 | 不只比较 JSON；禁止错误目标、重复移动或丢文件 |

概率和：本地内部全精度 p 要求非负、有效候选总和与 1 相差 ≤1e-6；外部接口若明确按 d 位小数返回，允许至多 `k × 0.5 × 10^-d + 浮点余量` 的舍入误差。不能因 200 个候选累计舍入误差误拒合法响应，也不能用无界归一化隐藏坏响应。Jev 按其实际协议单独验证。

### 近并列与动作边界

- 定义测试数值误差预算 εp（CPU FP32 初始 1e-4；其他 EP/精度独立验证），不可把显示四舍五入后的值用于判定。
- 参考 top-1 与第二名差距 >2εp 且远离所有自动执行策略边界的样本，要求排名/动作完全一致。
- 差距 ≤2εp 或落在策略阈值误差带的样本记录为数值敏感集。两个普通分类接近时暂存待决；真实类别与特殊项接近时也不得自动移动。不能靠“总一致率 99%”放过这组危险翻转。
- 两条路径都应用相同、冻结的安全策略；GPU 不合格只关闭对应 GPU 后端，不关闭 CPU 人工整理。运行时不必每次同时运行 PyTorch/CPU 双重验证。
- 所有人工待决/拒绝响应/失效版本用例，worker 路径不得变成自动移动。输出并列的展示次序用稳定 ID 确定，但展示顺序不构成自动裁决。

## 5. 覆盖样本及变形测试

### 固定回归集

- 中文/英文/混合语言、阿拉伯 RTL、日文、emoji、组合字符/NFC-NFD、空白/引号/换行、literal mask token、长数字和 Unicode 路径；输入与分类说明都要覆盖。
- 空分类应在请求前提示配置；正常请求含两个特殊项。覆盖总候选 3/5/10/20/50/200、类型边界和实际最大支持数；255 是服务选项上限，不是所有 Laya checkpoint 的可用 token 预算。
- 空文件名元数据、模糊名、同名不同简介、真实类别近并列、两个特殊项先后排名、新建类别立即重判、类别删除/停用/改名。
- 长度覆盖注意力窗口前/等于/后一位（以实际配置为准）、max_len−1/max_len/max_len+1、head 预算将满/耗尽、截断后 marker 不齐、零 state 空间。不能静默丢弃候选或特殊项继续推理。
- 单条 vs 混合长短 batch（1/2/8，在声明支持范围内）、候选数不同的 batch、改变批内顺序/分组、最后不满 batch；padding 不能改变有效样本分布或动作。
- 固定候选顺序下 A/D 等价是硬要求；候选置换后分别与同顺序 oracle 对照，另报告模型的顺序敏感性，不能错误要求位置敏感模型概率完全不变。

### 变形与故障

- 等价输入重复调用/worker 重启/冷暖启动，输出在声明精度内一致；增添 padding 不改有效结果；关闭 prefix/token 缓存与开启时一致。
- 版本/cache key 至少覆盖 checkpoint、tokenizer、模板、类别 revision、语言和预算；改变任一项必须失效，分类描述不得共用旧缓存。
- 超时、取消、stdout 混入日志、截断帧、未知 requestId、worker 崩溃/OOM、GPU reset、挂起后恢复：不串请求，不重用旧结果，不产生文件操作。
- 模型升级中旧请求可完成但不得混用新 tokenizer/head；已提交任务按自己的版本收尾，新请求用原子激活后的版本；中断升级保留旧可用包。

## 6. 模型是否“分得对”另设门槛

等价不代表模型正确。至少 500 个去重、人工标注的真实/授权元数据样本作为初始冻结评测集，按语言/场景/候选数/特殊项分层；同一项目、同文件改名变体不得跨开发集和验收集。阈值/模板/校准只能用开发集调，不能看完验收失败后反复调到通过。

报告混淆矩阵、普通分类准确率、两种特殊项 precision/recall、自动执行覆盖率、错误自动移动数/自动执行数，以及 Brier/ECE 和每桶样本数。任何已知高风险回归项误自动移动都阻断；首发自动执行的目标错误率 ≤1%，并要求该比例的单侧 95% 置信上界 ≤1%。零错误时需要约 300 个实际自动执行样本才足以支持这一量级，500 个总样本不自动等于达标。样本不足的桶默认预览/人工确认，补充独立评测后再开放，不宣传保证正确率。

Jev 无可控权重，单独做协议/回放测试和经用户授权的在线质量评测，记录日期与返回模型版本；不要求 Jev 与 Laya 分布相等。在线集不上传真实私人文档。

## 7. CI 与发布证据

- 每个 PR：无需大模型的预处理 golden、协议校验、策略边界和文件事务故障测试。
- 模型/分词/推理代码变更：A–D CPU 全链路对照、冻结分类评测、干净环境 worker 测试。
- GPU 制品：对应 OS/架构/EP/驱动设备实测，列实际节点分配及 CPU fallback；没有硬件证据的后端标为未验证，不默认启用。FP16/INT8 是独立制品，不继承 FP32 成绩。
- release：从安装包启动 D 路径，离线复跑最小金标准集，完成 OOBE 下载→校验→激活→分类→撤销；保存 JUnit/JSON 指标、失败样本 ID、artifact hash 与环境清单。
- 升级任意 checkpoint/tokenizer/导出器/ORT/EP 后重跑相关门槛。发布 manifest 的“已验证”列表只能由真实报告生成，不能手工填通过。
